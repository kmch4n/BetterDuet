# 全体の仕組み

- 状態: Accepted
- 要件 ID の接頭辞: `CORE`、`NOTICE`
- 最終更新: 2026-10-17

各機能の仕様が共通して使う言葉、拡張機能の中の部品、保存する情報、画面に出すお知らせを定めます。機能ごとの仕様（`features/`）は、この文書の言葉を使って書きます。DUET 側の挙動は [duet-platform.md](duet-platform.md) を前提にします。

## 用語

| 用語 | 意味 |
|---|---|
| 画面 ID | DUET の画面を見分ける ID。画面のフォームの `action` の末尾のファイル名（例：`FB17001G`）。アドレスバーの URL は使わない |
| メニュー画面 | サイドメニューかヘッダーの「ホーム」から直接開ける画面。一覧は [duet-platform.md](duet-platform.md) の「画面 ID とメニュー」の表のとおり |
| 詳細画面 | メニュー画面以外の画面。一覧の行を押して開く画面など |
| 戻り先のメニュー画面 | 詳細画面を開く前に、そのタブで最後に表示していたメニュー画面。メニュー画面ではその画面自身 |
| フォームの型 | ある画面のフォームの `action` と hidden 項目（名前と値）の組。DUET に送信するときの形を決める |
| 最新の画面 | DUET のサーバーが「現在の画面」だと考えている画面。拡張機能が最後に正常な応答を受け取った画面で、そのフォームの型も含む |
| 最新のタブ | 最新の画面を表示しているタブ。ないこともある |
| 古いタブ | 最新のタブ以外で、DUET の画面を表示しているタブ |
| 共通の操作 | どの画面にもあるフォーム（`unloadform`、`member`、`menuform`）の送信。サイドメニュー、ヘッダーの「ホーム」（`unloadform:goHome`）、言語やスマホ版の切り替えがこれに当たる。ログアウトは Ajax なので別に扱う（CORE-006） |
| 画面固有の操作 | `form1` の操作。一覧の行の選択、登録や送信のボタン、ダウンロードなど |
| 着地ページ | `https://duet.doshisha.ac.jp/betterduet-landing`。DUET には存在しないパスで、サーバーは 404 を返すだけでセッションに影響しない（E-011）。拡張機能が GET を止めたときに、タブをいったんここに移す |
| 入り直し | 壊れたセッションの代わりに、入場ページ（`FB01090G.html`）から新しいセッションを始めること（E-010） |
| エラー画面 | DUET が返す「ページ間の移動でエラーが発生しました」または「認証エラー」の画面 |

## 部品

拡張機能は次の部品で動きます。部品の分け方はファイルの分け方を縛りませんが、責任の境目はこの表に従います。

| 部品 | 動く場所 | 責任 |
|---|---|---|
| 送信係 | Service Worker | DUET へのリクエストを1つずつ順に送る。最新の画面を記録する。拡張機能から DUET へのリクエストは、すべてここを通す |
| 画面の見張り | コンテンツスクリプト（DUET の画面） | 画面が読み込まれたら、画面 ID とフォームの型を送信係に知らせる。DUET の送信を横取りして送信係に回す |
| 早期フック | ページのスクリプト（`world: "MAIN"`、`document_start`） | DUET のスクリプトより先に動き、送信と「戻る」の監視を差し替える |
| 遮断ルール | `declarativeNetRequest` の静的ルール | `/gakusei/html/` への画面としての GET を着地ページに付け替える |
| 着地ページの係 | コンテンツスクリプト（着地ページ） | 付け替えられたタブを、DUET の画面に開き直す |
| お知らせ帯 | コンテンツスクリプト | 画面の上部に、拡張機能からのお知らせを表示する |

## 共通の要件

### CORE-001 画面を記録する

- 状態: Accepted
- 優先度: 必須

DUET の画面（`/gakusei/html/` 以下でエラー画面でないもの）が読み込まれるたびに、その画面 ID とすべてのフォームの型を記録し、最新の画面とする。そのタブを最新のタブとする。

遮断ルールがあるため、`/gakusei/html/` の画面が GET で表示されることはない。画面が表示されたなら、それは DUET への POST の応答であり、最新の画面だとみなせる。

受け入れ条件:
- タブ A でサイドメニュー「お知らせ」を押すと、最新の画面が `FB01701G` になり、最新のタブがタブ A になる
- 記録した情報は、`chrome.storage.session` 以外に保存しない

### CORE-002 タブごとの画面を記録する

- 状態: Accepted
- 優先度: 必須

タブごとに、表示している画面 ID、戻り先のメニュー画面、そのタブで表示した画面の履歴（「戻る」で使う。[back-navigation.md](features/back-navigation.md)）を記録する。

記録は、そのタブの DUET のオリジンの `sessionStorage` に置く。`sessionStorage` は、再読み込み、Chrome によるタブの破棄と再読み込み、タブの複製のどれでも、そのタブ（複製では複製先のタブ）に引き継がれる（E-024）。そのため、着地ページの係は Service Worker に問い合わせずに、そのタブが直前に表示していた画面を知ることができる。あわせて、記録を書いたタブの ID も書いておき、複製されたタブ（ID が違う）を見分けられるようにする。

`sessionStorage` に書くのは、画面 ID、タブの ID、履歴（画面 ID の並び）だけにする。フォームの型やトークンは書かない。

受け入れ条件:
- タブ A でホーム、登録科目一覧、科目の詳細画面と進むと、タブ A の画面は詳細画面、戻り先のメニュー画面は `FB17001G` になる
- タブ A を再読み込みしても、複製しても、着地ページで記録を読める

### CORE-003 DUET への送信を1つずつ順に送る

- 状態: Accepted
- 優先度: 必須

DUET への POST（画面の送信と、拡張機能の `fetch`）は、送信係が1つずつ順に送る。前の送信の応答が返り、最新の画面を更新し終えてから、次の送信を始める。待っている送信は、受け付けた順に送る。

画面の送信は、送信先のタブで次の画面の読み込みが始まった時点では終わりとせず、CORE-001 の記録が済んだ時点で終わりとする。30秒たっても記録が届かない場合は、その送信は失敗したものとして扱い、次の送信に進む。このとき最新の画面は変えない。

受け入れ条件:
- 2つのタブでサイドメニューを続けて素早く押しても、どちらのタブもエラー画面にならない

### CORE-004 DUET の送信を横取りする

- 状態: Accepted
- 優先度: 必須

DUET の画面で送信が起きたら（DUET の `_doAction3` などから `form.submit()` が呼ばれたとき）、すぐには送らずに送信係に回す。送信係は、送信元のタブと操作の種類から次のどれかを選ぶ。

| 送信元 | 操作 | 扱い |
|---|---|---|
| 最新のタブ | すべて | そのまま送る |
| 古いタブ | 共通の操作 | フォームの `action` と画面 ID を含む hidden 項目名を最新の画面のものに書き換えて送る（E-004）。詳細は [multi-tab.md](features/multi-tab.md) |
| 古いタブ | 画面固有の操作 | 送らない。詳細は [multi-tab.md](features/multi-tab.md) |

受け入れ条件:
- 最新のタブでの操作は、拡張機能がない場合と同じ結果になる
- `checkOnceTime` による二重送信の防止や、`hakiCheck` の確認ダイアログは、拡張機能がない場合と同じように働く

### CORE-005 ダウンロードの送信

- 状態: Accepted
- 優先度: 必須

アクション名に `Download` を含む `form1` の送信（`doDownload`、`doTyuiZikoDownload` など。E-018）は、ダウンロードとして扱う。ダウンロードは画面が移らないため、CORE-003 の「記録が済んだ時点」が来ない。送信係は、送信してから3秒たった時点で、この送信を終わったものとする。最新の画面は変えない。

ダウンロードの前後で、サーバーの現在の画面は変わらない（E-022）。

受け入れ条件:
- 最新のタブで登録科目一覧のダウンロードを押すとファイルが保存され、その後サイドメニューを押してもエラー画面にならない
- 古いタブでダウンロードを押すと、TAB-002 のとおり止まる

### CORE-006 ログアウトを見分ける

- 状態: Accepted
- 優先度: 必須

DUET のログアウトは、フォームの送信ではなく Ajax で `unloadform:closeWindow` を送る（E-021）。早期フックで、DUET の画面からの XHR のうち、送信内容の `unloadform:__link_clicked__` が `unloadform:closeWindow` のものを見分け、送信係に知らせる。送信係は、この時点でログアウトした状態とする（TAB-005）。

この XHR 自体は止めず、書き換えもしない。古いタブからのログアウトで DUET がエラーを返しても、利用者の意図はログアウトなので結果は同じになる。

E-018 の範囲では、ログアウト以外に Ajax で DUET に送る操作は見つかっていない。見つかった場合は、CORE-003 の順番に含めるかをこの文書に追記してから扱う。

受け入れ条件:
- どれかのタブで LOGOUT を押して確認ダイアログで「OK」を押すと、ログアウトした状態になる（TAB-005 の受け入れ条件で確かめる）

### CORE-007 ポップアップには手を加えない

- 状態: Accepted
- 優先度: 必須

シラバス、得点分布、授業公開、マニュアルなど、DUET がポップアップで開くページ（E-018）には手を加えない。これらは `/gakusei/html/` の画面ではないため、遮断ルールにも当たらない。

受け入れ条件:
- 登録科目一覧でシラバスを開くと、拡張機能がない場合と同じくポップアップでシラバスが開く

### CORE-008 権限とデータの扱い

- 状態: Accepted
- 優先度: 必須

- ホスト権限は `*://duet.doshisha.ac.jp/*` だけにする
- 使う Chrome の権限は `storage` と `declarativeNetRequest` だけにする。ほかの権限が必要になったら、この要件を先に変える
- 最新の画面とフォームの型は `chrome.storage.session` に置く。フォームの型にはセッションのトークンが含まれるため、ディスクに書き出す場所（`chrome.storage.local` など）やページから読める場所（`sessionStorage` など）には置かない
- タブごとの画面と履歴は、CORE-002 のとおり DUET のオリジンの `sessionStorage` に置く
- 画面の内容（氏名、成績、科目名など）は記録しない
- DUET 以外へは何も送らない

受け入れ条件:
- `manifest.json` の権限が上のとおりになっている
- ブラウザを閉じると、記録した情報が残らない

## お知らせ帯

拡張機能が利用者に伝えることがあるとき、DUET の画面の上部（`#contents` の先頭）に帯を出します。着地ページでは、ページの中央に同じ内容を出します。

### NOTICE-001 お知らせ帯の表示

- 状態: Accepted
- 優先度: 必須

- 帯には、種類に応じた色、本文、必要ならボタンを1つ置く
- 帯は右端の「×」で閉じられる。閉じなくても、次に画面が移れば消える
- 同じ帯を重ねて出さない
- 種類が「注意」の帯は `role="alert"`、それ以外は `role="status"` にする
- ボタンはキーボードで操作できる

| 種類 | 使う場面 |
|---|---|
| 情報 | 拡張機能が画面を開き直したことを伝える |
| 注意 | 操作を止めたことを伝え、次にできることを示す |

文言は、それぞれの機能の仕様で `NOTICE` の表として定めます。

受け入れ条件:
- 帯が出ている状態で画面の操作を続けられる（帯が画面の操作を隠さない）
- Tab キーで帯のボタンと「×」に移動でき、Enter で押せる
