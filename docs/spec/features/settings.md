# 設定画面と機能のオン・オフ

- 状態: Implemented
- 要件 ID の接頭辞: `SET`
- 最終更新: 2026-10-19

## この機能が解決すること

DUET には、まだ確かめていない動きが残っています。そこで BetterDuet が誤作動したとき、今の利用者には、拡張機能をまるごと外すか、`chrome://extensions` でオフにするしか手がありません。

BetterDuet は、ツールバーのアイコンから開く設定画面で、機能ごとにオン・オフを切り替えられるようにします。誤作動した機能だけを切り、残りの機能は使い続けられるようにすることが目的です。新しい機能を足すためのものではありません。

## 利用者から見た動き

- ツールバーの BetterDuet のアイコンを押すと、設定画面が開く
- 3つのスイッチがあり、最初はすべてオンになっている
- スイッチを切り替えると、その場で保存される。DUET の画面を再読み込みする必要はなく、拡張機能が DUET に何かを送ることもない
- 切り替えた設定は、DUET の画面を次に移ったときから効く（SET-006）
- 「タブとセッションの保護」をオフにすると、「戻る」のスイッチは押せなくなる（SET-003）

## スイッチの単位

スイッチは、利用者から見た機能のまとまりで3つにします。

| スイッチ | 設定のキー | 対象の要件 |
|---|---|---|
| タブとセッションの保護 | `protection` | CORE-001〜006、TAB-001〜005、GUARD-001〜004 |
| ブラウザの「戻る」 | `back` | BACK-001〜004 |
| 外部リンクを新しいタブで開く | `links` | LINK-001／002 |

「複数タブでの利用」と「セッションの保護と復帰」は、[product.md](../product.md) では別の機能ですが、1つのスイッチにまとめます。どちらも最新の画面の記録と送信の一本化（CORE-001〜004）の上にあり、片方だけを切ると、拡張機能がない場合よりも壊れやすい組み合わせが生まれるためです。たとえば、遮断ルールだけを残して古いタブの送信を素通しにすると、古いタブの送信でセッションが壊れたあとに、着地ページの係が入り直しを始めます。

「戻る」は、前の画面を開くために送信係を使うので、「タブとセッションの保護」がオンのときだけ使えます。外部リンクは DUET に何も送らないので、ほかのスイッチと関係なく切り替えられます。

## 要件

### SET-001 設定画面

- 状態: Implemented
- 優先度: 必須

`manifest.json` の `action.default_popup` に設定画面を置き、ツールバーのアイコンから開けるようにする。見た目と構成は、姉妹プロジェクトの BetterE-class の設定画面にならう。

- 左の列：アイコン、「BetterDuet」、バージョン（`manifest.json` の `version` を表示する）、カテゴリ、「使い方」と「不具合の報告」のリンク
- 右の列：選んだカテゴリの見出しと説明、スイッチの一覧。スイッチごとに名前、説明、補足を書く
- カテゴリは「保護と操作」（`protection`、`back`）と「リンク」（`links`）の2つ。項目が3つしかないので、BetterE-class にある設定の検索欄は置かない
- 「使い方」は README、「不具合の報告」は GitHub の Issues を新しいタブで開く

設定画面は DUET の画面に差し込むものではないので、NOTICE-002 の対象にしない。色やスイッチの形は BetterE-class の設定画面にそろえる。

文言は次の表のとおりにする。

| スイッチ | 名前 | 説明 |
|---|---|---|
| `protection` | タブとセッションの保護 | 複数のタブ、再読み込み、休止したタブへの切り替えで DUET がログアウトしないようにします |
| `back` | ブラウザの「戻る」 | 「戻る」で、そのタブで1つ前に見ていた画面を開き直します |
| `links` | 外部リンクを新しいタブで開く | 参照URLやマニュアルの PDF を、別ウィンドウではなく新しいタブで開きます |

すべてのスイッチに、補足として「DUET の画面を次に移ったときから効きます」と書く。`protection` には、オフにすると DUET 本来の動きに戻り、2つ目のタブや再読み込みでログアウトすることがある、という注意も書く。

受け入れ条件:
- ツールバーのアイコンを押すと設定画面が開き、バージョンが `manifest.json` と同じである
- Tab キーでカテゴリ、スイッチ、リンクの順に移動でき、Space でスイッチを切り替えられる
- スイッチは `role="switch"` を持ち、名前がスクリーンリーダーで読み上げられる（`<label>` で結び付ける）

### SET-002 設定の保存

- 状態: Implemented
- 優先度: 必須

- 設定は `chrome.storage.local` のキー `betterduet:settings` に、`{ protection, back, links }` の形（値はすべて真偽値）で保存する
- 既定値はすべて `true`。キーがない、値が真偽値でない、読み出しに失敗した、のどれでも、その項目は既定値として扱う。拡張機能を入れ直したあとも、更新したあとも、利用者が切り替えるまでは今までどおりすべてが動く
- 設定のほかには何も保存しない。CORE-008 の「セッションのトークンをディスクに書かない」はそのまま守る
- 既定値と、保存した値の読み取り（不正な値を既定値に直す処理）は `core.js` に置き、Service Worker、コンテンツスクリプト、設定画面で同じものを使う

受け入れ条件:
- `tests/core.test.js` で、空の値、真偽値でない値、知らないキーを含む値を読み取ると、3項目とも真偽値になり、欠けた項目は `true` になることを確かめる
- 設定画面でスイッチを切り替えて閉じ、開き直すと、切り替えた状態のままになっている

### SET-003 「タブとセッションの保護」をオフにする

- 状態: Implemented
- 優先度: 必須

`protection` がオフのとき、拡張機能は DUET の画面に何もしない。拡張機能を外した場合と同じ動きにする（P-5）。

- 遮断ルール（`rules.json` の `guard`）を無効にする。`chrome.declarativeNetRequest.updateEnabledRulesets` を使う（権限は今の `declarativeNetRequest` のままでよい）
- オフのときに読み込まれた DUET の画面では、画面の見張りは送信係に何も知らせず、早期フックを止める（`hook:disable`）。DUET の送信はそのまま DUET に届く
- 早期フックが止まったら、早期フックが受け取らずにおいた DUET 自身の `popstate` の処理を、改めて登録する。DUET 本来の「戻る」の警告に戻すためで、そうしないと「戻る」がブラウザの履歴の GET になり、セッションが壊れる
- ログアウトの XHR だけは、今までどおり送信係に知らせる（CORE-006）。DUET には何も送らず、あとで保護をオンに戻したときに、ログアウトしたタブを勝手に入り直させないためである
- `back` は、保存した値にかかわらずオフとして扱う。設定画面では `back` のスイッチを押せない状態（`aria-disabled`、見た目も薄くする）にし、「タブとセッションの保護がオフの間は使えません」と添える。保存した `back` の値は書き換えず、`protection` をオンに戻すと元の状態に戻る
- `links` には影響しない
- 着地ページの係は、設定にかかわらず今までどおり動く。着地ページに来るのは、遮断ルールが有効だったときに付け替えられたタブだけで、何もしなければ DUET の画面が出ないまま止まるためである
- 画面の見張りは、設定を読み終えるまで送信の判断を待つ。読み終える前に DUET の送信が起きても、オフならそのまま DUET に送る

受け入れ条件:
- `protection` をオフにして DUET のサイドメニューで画面を移ったあと、その画面で再読み込みすると、着地ページを通らずに DUET のエラー画面になる（拡張機能がない場合と同じ）
- 同じ状態で「戻る」を押すと、DUET の「戻る」の警告が出る
- 同じ状態で、拡張機能が `chrome.storage.session` の最新の画面を書き換えない

### SET-004 「戻る」をオフにする

- 状態: Implemented
- 優先度: 必須

`back` がオフのとき（`protection` がオフの場合を含む）、BACK-001〜004 をすべて行わない。

- 早期フックは、DUET 自身の `popstate` の処理を登録し直し、自分の `popstate` の処理と Alt+← の横取りをやめる。DUET 本来の「戻る」の警告に戻る
- 画面の見張りは、「戻る」のための送信をしない
- タブごとの履歴（CORE-002）は、今までどおり記録してよい。`back` をオンに戻したとき、オフの間に移った画面も履歴に入っているようにするため

受け入れ条件:
- `back` をオフにして画面を移ったあと、「戻る」を押すと DUET の警告が出て、画面は移らない
- 同じ状態で Alt+← を押しても、画面は移らない（DUET 自身が Alt+← のキーを止めるため、警告も出ない。E-037）

### SET-005 「外部リンクを新しいタブで開く」をオフにする

- 状態: Implemented
- 優先度: 必須

`links` がオフのとき、LINK-001 の書き換えをしない。リンクは DUET 本来の動き（別ウィンドウ）になる。

受け入れ条件:
- `links` をオフにしてメッセージ詳細を開き直すと、「参照URL」の `href` が `?newwindow=true#` のままで、押すと別ウィンドウで開く
- `tests/links.test.js` で、`links` がオフならリンクに手を加えないことを確かめる

### SET-006 切り替えが効き始める時点

- 状態: Implemented
- 優先度: 必須

- 遮断ルールのオン・オフは、切り替えた直後から効く
- それ以外は、画面ごとに、その画面が読み込まれた時点の設定で決める。読み込んだあとに設定が変わっても、その画面の動きは変えない。早期フックの差し替えを途中で付けたり外したりすると、その画面が最新かどうかを送信係が判断できなくなるためである
- 設定を切り替えても、拡張機能は DUET のタブを再読み込みしない。再読み込みは GET なので、`protection` がオフならセッションが壊れる（BetterE-class は切り替えでページを再読み込みするが、ここはまねない）
- `protection` がオフの間に読み込まれた画面は、オンに戻しても、次に画面を移るまで保護されない。設定画面の補足（SET-001）で伝える

受け入れ条件:
- DUET のタブを開いたまま `links` をオフにしても、そのタブのリンクは書き換わったまま。サイドメニューで画面を移ると、書き換わらなくなる
- 設定を切り替えたときに、DUET へのリクエストが1つも起きない（DevTools のネットワークで確かめる）

### SET-007 Service Worker の起動時に遮断ルールを合わせる

- 状態: Implemented
- 優先度: 必須

`updateEnabledRulesets` で変えた状態は、拡張機能の更新で `manifest.json` の初期値（有効）に戻ることがある。Service Worker は、起動したとき（`chrome.runtime.onInstalled`、`chrome.runtime.onStartup`）と、設定が変わったとき（`chrome.storage.onChanged`）に、遮断ルールの有効・無効を `protection` に合わせる。

受け入れ条件:
- `protection` をオフにしたまま拡張機能を再読み込みしても、遮断ルールが無効のままになる（`chrome.declarativeNetRequest.getEnabledRulesets` で確かめる）
- `tests/background.test.js` で、起動時と設定の変更時に、`protection` に応じて `updateEnabledRulesets` を呼ぶことを確かめる

## 今回は対象にしないこと

- **拡張機能全体を止める1つのスイッチ**：3つをすべてオフにすれば、拡張機能を外した場合と同じになる。Chrome の拡張機能の管理画面でもオフにできる
- **設定の同期**（`chrome.storage.sync`）：パソコンごとに誤作動の状況が違いうるため、端末ごとに持つ
- **オフになっている機能があることを、DUET の画面やアイコンのバッジで知らせること**
- **開発者向けの設定（デバッグ表示など）**

## 確認の記録

2026-10-19 に、Chrome 155 に `extension/` を読み込み、実際の DUET で確認しました。設定画面は、ツールバーのアイコンを本物のマウスで押して開き、スイッチも本物のクリックで切り替えました。`node --test tests/*.test.js` もすべて通っています。

| 要件 | 確認方法 |
|---|---|
| SET-001 | 実機：アイコンから設定画面が開き、バージョンが `v0.3.0`（`manifest.json` と同じ）、カテゴリの件数（`2/2` など）がスイッチに合わせて変わった。テスト：`tests/manifest.test.js`（`action.default_popup`、参照するファイル、`role="switch"` と `<label>`）。Tab キーと Space での操作、スクリーンリーダーでの読み上げは実機で試していない |
| SET-002 | 実機：切り替えて閉じ、開き直すと、切り替えた状態のままだった。テスト：`tests/core.test.js`（不正な値、欠けた項目、読み出しの失敗） |
| SET-003 | 実機：オフにしたあとサイドメニューで「お知らせ」に移ると、タブの記録（`sessionStorage`）が更新されなかった。その画面で「戻る」を押すと DUET の警告が出て、再読み込みすると着地ページを通らずに DUET の認証エラーになった。設定画面では「戻る」のスイッチが薄くなり、押しても変わらず、保護をオンに戻すと元のオンに戻った。テスト：`tests/early-hook.test.js`、`tests/core.test.js` |
| SET-004 | 実機：「戻る」だけをオフにして画面を移り、ツールバーの「戻る」を押すと DUET の警告が出て、画面はそのままだった。Alt+← では何も起きなかった。オンに戻して画面を移ると、「戻る」で前の画面が開いた（オフの間に移った画面も履歴に入っていた）。テスト：`tests/early-hook.test.js` |
| SET-005 | 実機：オフにしてマニュアルを開くと、11件のリンクがどれも `?newwindow=true#` のままだった。テスト：`tests/links.test.js` |
| SET-006 | 実機：マニュアルを開いたまま外部リンクをオンに戻しても、その画面のリンクは書き換わらず、画面を移ってから「戻る」でマニュアルを開くと11件が書き換わった。切り替えで DUET のタブは再読み込みされなかった。ネットワークの記録は取っていないが、設定画面のコードは `chrome.storage.local` に書くだけで、DUET には触れない |
| SET-007 | 実機：保護をオンに戻したあと、SSO ポータルから入り直して再読み込みすると、着地ページを通って画面が開き直された（遮断ルールが戻った）。テスト：`tests/background.test.js`、`tests/manifest.test.js`。オフのまま拡張機能を再読み込みする確認は、実機では行っていない |
