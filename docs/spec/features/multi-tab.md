# 複数タブでの利用

- 状態: Accepted
- 要件 ID の接頭辞: `TAB`
- 最終更新: 2026-10-17

## この機能が解決すること

DUET を2つ以上のタブで開き、行き来しながら使えるようにします。

DUET のサーバーは、セッションごとに「現在の画面」を1つしか持たず、それに合わない送信を受けるとセッションを破棄します（[duet-platform.md](../duet-platform.md)）。BetterDuet は最新の画面を記録し、古いタブからの送信を最新の画面に合わせて送り直します（[architecture.md](../architecture.md) の CORE-004）。DUET から見ると、ずっと1つのタブで操作しているように見えます。

新しいタブの開き方は、Chrome の普段の操作（タブの複製、SSO ポータルから開く）のままです。新しく覚える操作はありません。

## 利用者から見た動き

- **新しいタブを開く**：DUET のタブを複製するか、SSO ポータルから DUET を開くと、もう1つ DUET のタブができる。どちらのタブも使える
- **タブを行き来する**：どのタブでも、サイドメニューやヘッダーの操作はそのまま使える
- **古いタブの中のボタン**：別のタブで操作したあと、古いタブの一覧の行や登録ボタンなどを押すと、送らずに止めて帯で知らせる。帯のボタンで、そのタブの画面を開き直せる

## 要件

### TAB-001 古いタブで共通の操作ができる

- 状態: Accepted
- 優先度: 必須

古いタブで共通の操作（サイドメニュー、ヘッダーの「ホーム」、言語やスマホ版の切り替え）をしたら、フォームを最新の画面の型に書き換えて送る。書き換えるのは、フォームの `action` と、画面 ID を名前に含む hidden 項目（`<フォームID>/html/fb/…`）の名前だけで、`__link_clicked__` の値（押した操作）はそのまま使う。

受け入れ条件:
- タブ A でホームを開いたまま、タブ B で「お知らせ」を開く。その後タブ A で「よくある質問」を押すと、タブ A に「よくある質問」が表示される
- 続けてタブ B で「マニュアル」を押すと、タブ B に「マニュアル」が表示される
- 以上の操作のあいだ、どのタブもエラー画面にならない

### TAB-002 古いタブの画面固有の操作は送らずに止める

- 状態: Accepted
- 優先度: 必須

古いタブで画面固有の操作（`form1` の送信）をしたら、送信しない。そのタブに NOTICE-TAB-1 の帯を出す。帯のボタンを押したら、そのタブの戻り先のメニュー画面を開き直す。

画面固有の操作には、一覧の行の選択、ダウンロード、登録や送信のボタンが含まれる。最新の画面に同じボタンがないため、送るとセッションが壊れる（E-003）。

開き直すときは、最新の画面の型のフォームに、戻り先のメニュー画面を開くアクション（[duet-platform.md](../duet-platform.md) の「画面 ID とメニュー」の表。ホームなら `unloadform:goHome`）を入れて、そのタブで送信する。開き直したタブは最新のタブになる。

受け入れ条件:
- タブ A で登録科目一覧を開いたまま、タブ B で成績確認を開く。その後タブ A で科目の行を押すと、画面は移らず、タブ A に NOTICE-TAB-1 の帯が出る。どのタブもエラー画面にならない
- 帯の「この画面を開き直す」を押すと、タブ A に登録科目一覧が表示される。その後タブ A で科目の行を押すと、通常どおり進める

### TAB-003 タブを複製すると、同じ画面のタブがもう1つできる

- 状態: Accepted
- 優先度: 必須

DUET のタブを Chrome の「複製」で複製したら、新しいタブに複製元のタブと同じ画面を開く。複製元が詳細画面なら、戻り先のメニュー画面を開く。

複製したタブは GET を送るため、遮断ルールで着地ページに移る（E-015）。着地ページの係が、複製元のタブの記録をもとに画面を開き直す（[session-guard.md](session-guard.md) の GUARD-002）。

複製元の画面は、複製先のタブに引き継がれた `sessionStorage` の記録（CORE-002、E-024）から分かる。`openerTabId` は複製元を指さないため使わない（E-023）。記録がない場合はホームを開く。

受け入れ条件:
- 成績確認を表示しているタブ A を複製すると、新しいタブ B に成績確認が表示される。タブ A は成績確認のまま残る
- その後、タブ A とタブ B のどちらでサイドメニューを押しても、どのタブもエラー画面にならない

### TAB-004 SSO ポータルから開くと、DUET のタブがもう1つできる

- 状態: Accepted
- 優先度: 必須

DUET のセッションが生きているときに、SSO ポータルから DUET を開いたら、新しいタブにホームを開く。ほかの DUET のタブはそのまま使える。セッションが生きていないときは、入り直して「お知らせ」を開く（GUARD-002 の 1）。

ポータルからの入場は `FB01090G.html` への GET で、セッションが生きているときに DUET に届くとセッションが壊れる（E-006、E-008）。遮断ルールで着地ページに移し、着地ページの係がホームを開く（GUARD-002）。

セッションが生きていないときに「お知らせ」を開くのは、DUET 本来の入場ページ（大学からのお知らせ）と同じ内容で、拡張機能がない場合と同じ流れにするため。

受け入れ条件:
- DUET のタブ A で成績確認を開いたまま、SSO ポータルから DUET を開くと、新しいタブ B にホームが表示される。その後タブ A でサイドメニューを押すと、通常どおり進める
- DUET のタブが1つもなく、セッションも生きていない状態で SSO ポータルから DUET を開くと、「お知らせ」（大学からのお知らせ）が表示される

### TAB-005 ログアウトしたら、ほかのタブも入り直さない

- 状態: Accepted
- 優先度: 必須

どれかのタブでログアウトしたら（CORE-006）、ほかの DUET のタブで操作しても、入り直し（GUARD-003）をしない。代わりに NOTICE-TAB-2 の帯を出す。利用者が SSO ポータルから DUET を開いたら、この状態を解く。

ログアウトは利用者の意思なので、拡張機能が勝手に入り直してはならない。

受け入れ条件:
- タブ A でログアウトしたあと、タブ B でサイドメニューを押すと、画面は移らず NOTICE-TAB-2 の帯が出る
- その後 SSO ポータルから DUET を開くと、DUET の画面が表示され、以降は通常どおり使える

## お知らせの文言

| ID | 種類 | 本文 | ボタン |
|---|---|---|---|
| NOTICE-TAB-1 | 注意 | 別のタブで DUET を操作したため、このタブの画面は古くなっています。この操作を続けるには、画面を開き直してください。 | この画面を開き直す |
| NOTICE-TAB-2 | 注意 | DUET からログアウトしています。続けるには、SSO ポータルから DUET を開き直してください。 | SSO ポータルを開く（`https://doshisha.ex-tic.com/idm/user/portal/` を新しいタブで開く） |

## 今回は対象にしないこと

- **古いタブの画面固有の操作を通すこと**：サーバーをそのタブの画面まで戻してから送れば通せる（E-004）。ただし詳細画面まで戻すには、そこまでの操作を順に送り直す必要がある。失敗したときの影響も考えると、今回は TAB-002 のとおり止める。将来、閲覧だけの操作から対応を検討する
- **入力中の内容の保護**：画面を開き直すと入力欄は空になる。将来の候補
