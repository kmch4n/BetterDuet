# セッションの保護と復帰

- 状態: Accepted
- 要件 ID の接頭辞: `GUARD`
- 最終更新: 2026-10-17

## この機能が解決すること

利用者が何も悪いことをしていないのに DUET が使えなくなり、SSO ポータルからやり直しになる状況をなくします。

原因の大半は、ブラウザが DUET の画面を GET で開き直すことです。再読み込み、タブの複製、メモリセーバーで休止したタブへの切り替え、ブラウザの再起動時のタブ復元、SSO ポータルからの開き直しが、どれも GET になります（E-006、E-014〜E-016）。DUET はこの GET を不正な遷移とみなし、セッションを破棄します。

BetterDuet はこの GET を DUET に届く前に止め、そのタブで元の画面を開き直します。それでもセッションが壊れていた場合は、SSO ポータルを通らずに入り直します。

## 利用者から見た動き

- 再読み込みボタンを押すと、同じ画面がもう一度表示される
- 休止していたタブに戻ると、同じ画面が表示される
- セッションが切れていても、操作すれば拡張機能が入り直し、目的の画面が表示される。SSO のログインまで切れている場合だけは、SSO ポータルからやり直す

いずれも、詳細画面にいた場合は戻り先のメニュー画面が表示されます。入力中の内容は残りません。

## 要件

### GUARD-001 画面としての GET を DUET に届けない

- 状態: Accepted
- 優先度: 必須

`https://duet.doshisha.ac.jp/gakusei/html/` で始まる URL への `main_frame` の GET を、`declarativeNetRequest` の静的ルールで着地ページにリダイレクトする（E-012）。リダイレクト先の URL のクエリに、元の URL のパス（`/gakusei/html/` 以降）を `from` として付ける。

入場ページ（`FB01090G.html`）への GET も対象にする。セッションが生きているときに届くとセッションが壊れるため（E-006）。

POST と、`main_frame` 以外（`fetch`、XHR、画像やスクリプトの読み込み）は対象にしない。

静的ルールにするのは、ブラウザの起動直後や Service Worker が止まっている間にも効かせるため。

受け入れ条件:
- DUET の画面を表示しているタブで再読み込みすると、DUET に GET が送られない（DevTools の Network で確認する）
- アドレスバーに `https://duet.doshisha.ac.jp/gakusei/html/fb/fb010/FB01002G.html` を入力して開くと、DUET に GET が送られない
- 拡張機能を無効にすると、上のどちらも DUET に GET が送られる（ルールが拡張機能だけに依存していることの確認）

### GUARD-002 着地したタブで画面を開き直す

- 状態: Accepted
- 優先度: 必須

着地ページが開いたら、着地ページの係が、開き直す画面を次の順で決め、そのタブで開く。

1. 元の URL（リダイレクト先のクエリの `from`）が入場ページ（`fb/fb010/FB01090G.html`）なら、利用者が DUET に入ろうとしたものとして扱う。ログアウトした状態（TAB-005）を解く。セッションが生きていればホームを、生きていなければ GUARD-003 で入り直して「お知らせ」（`FB01701G`）を開く
2. そのタブの `sessionStorage` に CORE-002 の記録があれば、その戻り先のメニュー画面。再読み込み、休止したタブ、タブの復元、タブの複製（TAB-003）のどれでもこの記録が残っている（E-024）
3. どちらでもなければ、ホーム（URL の直接入力、ブックマーク）

1 で「お知らせ」を開くのは、DUET 本来の入場ページ（大学からのお知らせ）と同じ内容の画面で、拡張機能がない場合と同じ流れにするため。

ログアウトした状態のときは、1 以外では画面を開かず、着地ページに NOTICE-TAB-2 の内容を表示する。

記録を書いたタブの ID が自分と違えば複製されたタブなので、開き直したあとに自分のタブの ID で記録を書き直す（履歴は複製元のものを引き継ぐ）。

開くときは、送信係を通して、最新の画面の型のフォームにその画面を開くアクション（ホームなら `unloadform:goHome`）を入れ、着地ページのタブで送信する（E-013、E-020）。最新の画面の記録がない場合や、セッションが生きていない場合は、GUARD-003 で入り直してから開く。

開いている間は、着地ページに「DUET を開いています…」と表示する。開き直したあと、タブ自身の記録に詳細画面が残っていた場合は、NOTICE-GUARD-1 の帯を出す。

受け入れ条件:
- 成績確認を表示しているタブで再読み込みすると、同じタブに成績確認が表示される。ほかの DUET のタブもそのまま使える
- 登録科目一覧から科目の詳細画面を開いた状態で再読み込みすると、登録科目一覧が表示され、NOTICE-GUARD-1 の帯が出る
- 着地ページのタブで、DUET の 404 の本文（Not Found）が見えたまま止まらない

### GUARD-003 セッションが生きていなければ入り直す

- 状態: Accepted
- 優先度: 必須

次のどちらかのときは、入り直してから、目的の画面を開く。

- DUET の応答がエラー画面だったとき（利用者の操作の結果でも、拡張機能の送信の結果でも）
- 着地ページで画面を開こうとしたとき、最新の画面の記録がないとき

入り直しは、送信係が次の順で送る（E-010）。途中の応答はタブに表示しない。

1. `fetch` で `/gakusei/html/fb/fb010/FB01090G.html` を GET する
2. 返ってきたページの `form1` で `goHome` を `fetch` で POST する。返ってきたホームを最新の画面として記録する
3. 目的の画面を開くアクションを、最新の画面の型のフォームに入れ、対象のタブで送信する。目的の画面がホームでも、2 の応答はタブに表示されていないため、`unloadform:goHome` を送信してタブに表示する

目的の画面は、エラー画面になったタブの戻り先のメニュー画面とする。ただし、エラーになった操作がメニュー画面を開く操作だった場合は、その画面とする。

入り直しは、利用者の1回の操作につき1回までとする。入り直しのあとも目的の画面を開けなかったら、それ以上は送らず、NOTICE-GUARD-3 の帯を出す。

TAB-005 のログアウト後の状態では、入り直さない。

受け入れ条件:
- タブ A でホームを開いている状態で、拡張機能を使わずにセッションを壊す（例：拡張機能を一時的に無効にして DUET の URL を直接開き、そのあと有効に戻す）。その後タブ A で「お知らせ」を押すと、タブ A に「お知らせ」が表示され、SSO ポータルを通る必要がない
- 入り直しが成功したとき、NOTICE-GUARD-2 の帯が出る

### GUARD-004 SSO のログインが切れていたら、ポータルへ案内する

- 状態: Accepted
- 優先度: 必須

GUARD-003 の手順 1 で、応答が DUET の入場ページでなかったら（リダイレクトで `duet.doshisha.ac.jp` 以外に移った、または入場ページの `form1` に `goHome` がない）、SSO のログインが切れたものとして、入り直しをやめる。対象のタブに NOTICE-GUARD-4 の帯を出す。

SSO のログインが切れた状態の応答は確かめていない。実装のときに確かめ、[duet-platform.md](../duet-platform.md) に記録する。

受け入れ条件:
- SSO のログインが切れた状態で DUET を操作すると、NOTICE-GUARD-4 の帯が出て、帯のボタンで SSO ポータルが開く。拡張機能が DUET に送信を繰り返さない

## お知らせの文言

| ID | 種類 | 本文 | ボタン |
|---|---|---|---|
| NOTICE-GUARD-1 | 情報 | 再読み込みのため、一覧の画面を開き直しました。詳細の画面は開き直せません。 | なし |
| NOTICE-GUARD-2 | 情報 | DUET のセッションが切れていたため、自動で入り直しました。 | なし |
| NOTICE-GUARD-3 | 注意 | DUET を開き直せませんでした。SSO ポータルから DUET を開き直してください。 | SSO ポータルを開く |
| NOTICE-GUARD-4 | 注意 | SSO のログインが切れています。SSO ポータルからログインし直してください。 | SSO ポータルを開く |

「SSO ポータルを開く」は `https://doshisha.ex-tic.com/idm/user/portal/` を新しいタブで開きます。

## 今回は対象にしないこと

- **無操作による期限切れの防止**：期限は不明（E-005）。切れたあとは GUARD-003 で入り直せるため、定期的に通信して延命することはしない（[product.md](../product.md) の P-2）
- **入力中の内容の保護**：将来の候補
- **ショートカットキー（F5 など）の復活**：DUET が無効にしているキーは、今回はそのまま。再読み込みはブラウザのボタンから行える
