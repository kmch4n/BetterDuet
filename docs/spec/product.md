# プロダクト仕様

- 状態: Draft
- 最終更新: 2026-10-17

## 目的

同志社大学の DUET を、複数のタブで開いても壊れないようにすることが最初の目的です。

DUET は、同じセッションで2つ目のタブを開くと、両方のタブがまとめてログアウトされます。科目一覧を見ながら成績を確認する、といった普通の使い方ができず、そのたびに SSO からログインし直すことになります。BetterDuet はこの問題を拡張機能の側で吸収し、DUET を普通の Web サイトと同じ感覚で使えるようにします。

## 対象

- 対象のサイト：`https://duet.doshisha.ac.jp/gakusei/` 以下（学生向け画面）
- 対象のブラウザ：Google Chrome（Manifest V3）
- 対象の利用者：DUET を使う同志社大学の学生

## 全機能に共通する原則

### P-1 セッションを壊さない

拡張機能が送るリクエストが原因で、利用者がログアウトされることがあってはなりません。DUET は想定外のリクエストを1回受けただけでセッションを破棄します（[duet-platform.md](duet-platform.md)）。そのため、DUET へのリクエストはすべて拡張機能内の1つの経路に集め、順番に送ります。機能ごとに個別にリクエストを送ってはいけません。

### P-2 利用者の操作にひも付いたリクエストだけを送る

バックグラウンドでの巡回、定期的な取得、ページの一括保存はしません。リクエストは、利用者が押したボタンや開いたタブを実現するのに必要なものだけにします。

### P-3 データを外に出さない

DUET の画面には氏名、学生番号、成績、履修科目が含まれます。拡張機能はこれらを DUET 以外へ送信しません。保存するのは動作に必要な最小限の情報（画面 ID やフォームの形など）に限り、成績などの内容そのものは保存しません。

### P-4 状態を変える操作は慎重に扱う

履修登録、履修中止、アンケートの送信、連絡先の変更、メッセージの返信のように DUET 側のデータを変える操作は、失敗したときの影響が大きい操作です。こうした操作に拡張機能が手を加える場合は、その機能の仕様で個別に要件を定めます。定めのない操作は、DUET 本来の動作のまま通します。

### P-5 失敗したら DUET 本来の動作に戻す

DUET の HTML は予告なく変わります。前提にしている要素が見つからない場合、拡張機能は何もせず、DUET 本来の動作に任せます。

## やらないこと

- DUET 以外の同志社大学のサービス（e-class など）への対応。e-class は [BetterE-class](https://github.com/kmch4n/BetterE-class) が扱います
- 教職員向け画面への対応
- ログイン（SSO）の自動化や、パスワードの保存
- DUET の画面デザインの全面的な作り直し
