# プロダクト仕様

- 状態: Draft
- 最終更新: 2026-10-17

## 目的

DUET を使っていて、何も悪いことをしていないのに使えなくなり、開いていた画面がすべて失われ、SSO ポータルからやり直しになる。BetterDuet は、この状況をなくすことを最初の目的にします。

DUET のサーバーは、セッションごとに「現在の画面」を1つしか持たず、それに合わないリクエストを1回でも受けるとセッションを破棄します（[duet-platform.md](duet-platform.md)）。2つ目のタブを開く、再読み込みする、休止していたタブに戻る、SSO ポータルから開き直す、といった普通の操作がこれに当たります。BetterDuet はこれらの操作を拡張機能の側で吸収し、DUET を普通の Web サイトと同じ感覚で使えるようにします。

## 対象

- 対象のサイト：`https://duet.doshisha.ac.jp/gakusei/` 以下（学生向け画面）
- 対象のブラウザ：Google Chrome（Manifest V3）
- 対象の利用者：DUET を使う同志社大学の学生

## 最初のリリースに含める機能

| 機能 | 仕様 | できるようになること |
|---|---|---|
| 複数タブでの利用 | [features/multi-tab.md](features/multi-tab.md) | タブの複製や SSO ポータルから、DUET のタブを増やして行き来できる |
| セッションの保護と復帰 | [features/session-guard.md](features/session-guard.md) | 再読み込みや休止したタブへの切り替えで壊れない。壊れても SSO ポータルを通らずに戻れる |

3つの機能は、[architecture.md](architecture.md) の共通の仕組み（最新の画面の記録と、送信の一本化）の上に作ります。

## 全機能に共通する原則

### P-1 セッションを壊さない

拡張機能が送るリクエストが原因で、利用者がログアウトされることがあってはなりません。DUET へのリクエストはすべて拡張機能内の1つの経路（[architecture.md](architecture.md) の送信係）に集め、順番に送ります。機能ごとに個別にリクエストを送ってはいけません。

### P-2 利用者の操作にひも付いたリクエストだけを送る

バックグラウンドでの巡回、定期的な取得、セッションを延命するための通信、ページの一括保存はしません。リクエストは、利用者が押したボタンや開いたタブを実現するのに必要なものだけにします。

### P-3 データを外に出さない

DUET の画面には氏名、学生番号、成績、履修科目が含まれます。拡張機能はこれらを DUET 以外へ送信しません。保存するのは動作に必要な最小限の情報（画面 ID やフォームの型など）に限り、ブラウザを閉じれば消える場所に置きます。成績などの内容そのものは保存しません。

### P-4 送ったら壊れる操作は、送らずに止める

拡張機能が安全に送れることを保証できない操作は、送らずに止め、何が起きたかと次にできることを画面に表示します。履修登録やアンケートの送信など、DUET 側のデータを変える操作も、この原則で扱います。止めた操作を、拡張機能が勝手に別の形で送り直すことはしません。

### P-5 前提が崩れたら DUET 本来の動作に戻す

DUET の HTML は予告なく変わります。前提にしている要素が見つからない場合、拡張機能は何もせず、DUET 本来の動作に任せます。

## やらないこと

- 入力中の内容の保護。画面を開き直すと入力欄は空になる（将来の候補）
- 無操作による期限切れの防止。期限は DUET 側の都合で、拡張機能では延ばさない
- SSO のログインの自動化や、パスワードの保存。SSO のログインが切れたときは、SSO ポータルからやり直してもらう
- 「進む」と、詳細画面への「戻る」
- ショートカットキー（F5 など）の復活（将来の候補）
- DUET 以外の同志社大学のサービス（e-class など）への対応。e-class は [BetterE-class](https://github.com/kmch4n/BetterE-class) が扱う
- 教職員向け画面への対応
- DUET の画面デザインの全面的な作り直し

## 実装の前に確かめること

次の3点は、仕様の前提のうち確かめていないことです。実装を始めたら最初に確かめ、[duet-platform.md](duet-platform.md) に記録します。結果が想定と違えば、該当する要件を先に直します。

| 確かめること | 関係する要件 |
|---|---|
| ダウンロードのあと、サーバーの現在の画面が変わらないか（利用者の許可を得て実際にダウンロードする） | CORE-005 |
| タブの複製で、Chrome が新しいタブに `openerTabId` を渡すか | TAB-003 |
| SSO のログインが切れた状態で入場ページを取得すると、何が返るか | GUARD-004 |
